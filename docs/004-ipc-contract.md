# Контракт межпроцессного взаимодействия (IPC Contract)

Документ определяет спецификацию протокола взаимодействия между привилегированной службой `service` и непривилегированным приложением в трее `tray`. Все типы данных соответствуют [Доменному контракту](./002-domain-contract.md).

## 1. Архитектура и безопасность транспорта IPC

1. **Транспорт (Transport)**:
   * Локальные именованные каналы Windows (Windows Named Pipes) в пространстве ядра (например, `\\.\pipe\palka_ipc_v1`).
2. **Адресный контроль доступа (Scoped Security Descriptors / ACL)**:
   * Дескриптор безопасности канала ДОЛЖЕН (SHALL) предоставлять доступ строго ограниченному набору субъектов:
     * `NT AUTHORITY\SYSTEM`: Полный доступ (Generic All);
     * `BUILTIN\Administrators`: Полный доступ (Generic All);
     * `Child User SID` (сконфигурированная учетная запись ребенка): Чтение и запись (Generic Read / Write);
     * `Network Logon` / `Anonymous`: **Безусловный запрет доступа (Access Denied)**.
3. **Модель доверия и проверка контекста вызывающего**:
   * Клиент `tray` рассматривается службой как **недоверенный (Untrusted)**.
   * `service` проверяет контекст безопасности вызывающего процесса (через функции имперсонации и токены доступа Windows API) при установлении соединения, предотвращая подмену идентификатора вызывающего.

## 2. Разделение операций по уровню привилегий

### 2.1. Не требующие авторизации (Unprivileged / No PIN required)
Доступны любому подключенному экземпляру `tray` в сессии целевого пользователя:
* `QueryStatus` — запрос снимка состояния системы ([`StatusSnapshot`](./002-domain-contract.md)).
* `SendChildMessage { text }` — отправка текстового сообщения от ребенка родителям в Telegram.
* `SubscribeEvents` — **управляющий запрос протокола IPC** (IPC Transport Control Request, не являющийся доменной `Command`), инициирующий непрерывную передачу потока событий от службы к клиенту.

### 2.2. Защищенные PIN-кодом (PIN Protected / Privileged)
Требуют авторизации родителя:
* `ScheduleInternetBlock { duration_minutes }` (при вызове из локального трея);
* `ImmediateInternetBlock`;
* `CancelInternetBlockTimer`;
* `RestoreInternet` (снятие блокировки интернета);
* `ScheduleShutdown { duration_minutes }`;
* `CancelShutdownTimer`.

## 3. Авторитетная проверка PIN-кода и сессионные токены

1. **Авторитетность службы**:
   * Валидация введенного PIN-кода производится исключительно в `service`.
   * Хэш PIN-кода (Argon2id) хранится в защищенном хранилище службы и недоступен процессу `tray`.
2. **Защита от перебора (Rate Limiting & Lockout)**:
   * `service` ведет авторитарный счетчик неудачных попыток ввода PIN.
   * После 3 (трех) подряд неверных попыток служба активирует временную блокировку (30 секунд, 1 минута, 5 минут).
   * Информация о блокировке возвращается в `PinAuthenticationResult { success: false, lock_timeout_seconds: Some(...) }`.
3. **Краткосрочные сессионные токены**:
   * При успешной валидации PIN служба генерирует непрозрачный случайный токен авторизации (Authorization Token).
   * **Свойства токена**:
     * хранится исключительно в оперативной памяти службы (никогда не сохраняется на диск);
     * имеет строго ограниченное время жизни (TTL не более 5 минут);
     * становится недействительным при перезапуске службы;
     * криптографически или контекстно привязывается к дескриптору конкретного локального IPC-соединения, исключая возможность его переиспользования другим процессом.

## 4. Двусторонний чат и стриминг событий

1. **Поток событий (Service -> Tray)**:
   * При получении запроса `SubscribeEvents` служба отправляет актуальный [`StatusSnapshot`](./002-domain-contract.md).
   * В дальнейшем служба асинхронно пушит события `Event` (`WarningThresholdReached`, `ChatMessageReceived`, `InternetStateChanged`, `ServiceHealthUpdated`).
2. **Маршрутизация сообщений (Tray -> Service -> Telegram)**:
   * Сообщение ребенка валидируется службой на размер и формат.
   * `service` присваивает сообщению `MessageId`, сохраняет его в персистентную очередь и инициирует доставку в Telegram.
