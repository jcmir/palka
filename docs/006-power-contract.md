# Контракт управления питанием (PowerController Contract)

Документ определяет абстрактный контракт компонента `PowerController`, отвечающего за принудительное завершение работы операционной системы Windows.

## 1. Абстрактный интерфейс `PowerController`

`PowerController` является абстрактным интерфейсом подсистемы `windows-platform`, инкапсулирующим вызовы Windows API для управления питанием.

```rust
// Концептуальное представление интерфейса PowerController
trait PowerController: Send + Sync {
    /// Инициировать выключение компьютера с заданным льготным таймаутом (grace period)
    fn initiate_shutdown(&self, grace_period_seconds: u32, force: bool) -> Result<(), PowerError>;

    /// Отменить инициированное выключение компьютера
    fn abort_shutdown(&self) -> Result<(), PowerError>;

    /// Запросить статус готовности подсистемы управления питанием
    fn check_privileges(&self) -> Result<(), PowerError>;
}
```

## 2. Нормативные правила и семантика выключения

1. **Режимы завершения работы (Graceful vs Forced Shutdown)**:
   * При наступлении дедлайна таймера выключения `service` вызывает `initiate_shutdown` с коротким льготным периодом (grace period, по умолчанию 15–30 секунд), давая приложениям возможность сохранить несохраненные данные.
   * По истечении льготного периода операционная система производит принудительное выключение (`force = true`), предотвращая блокировку выключения зависшими пользовательскими процессами или диалогами сохранения файлов.
2. **Необходимые привилегии**:
   * Для корректного исполнения выключения служба `service` ДОЛЖНА (SHALL) обладать системной привилегией `SeShutdownPrivilege`.
   * При инициализации служба вызывает `check_privileges()` для валидации наличия необходимых прав в токене процесса.
3. **Отмена выключения**:
   * При поступлении авторизованной команды `CancelShutdownTimer` (из Telegram или локально через PIN) в процессе ожидания выключения, служба немедленно вызывает `abort_shutdown()`, отменяя системный вызов Windows и возвращая систему в `ShutdownState::Idle`.

## 3. Обработка ошибок
* Если системный вызов выключения завершается ошибкой (например, отказ в правах или конфликт системных служб), генерируется ошибка `PowerError`, событие фиксируется в журнале службы, а родителям отправляется уведомление об ошибке через Telegram.
