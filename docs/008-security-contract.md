# Контракт безопасности (Security Contract)

Документ определяет модель угроз, границы доверия, политики изоляции привилегий и правила защиты компонентов системы.

## 1. Модель угроз и границы ответственности (Threat Model & Scope)

### 1.1. Классификация субъектов
* **Ребенок (Child)**: Обладает учетной записью **Стандартного пользователя Windows (Standard User)**. Является потенциальным нарушителем, стремящимся обойти временные ограничения, продлить доступ в сеть или предотвратить выключение компьютера.
* **Родитель (Parent)**: Обладает учетной записью **Администратора Windows (Administrator)**. Является доверенным оператором системы.

### 1.2. Границы защищенности от стандартного пользователя (In Scope)
Стандартный пользователь Windows **КАТЕГОРИЧЕСКИ НЕ ДОЛЖЕН (SHALL NOT)** иметь возможности:
1. Остановить или приостановить службу через Service Control Manager (`sc.exe`, `net.exe`, `Stop-Service`, Services MMC).
2. Изменить конфигурацию запуска или удалить службу из системы.
3. Перезаписать, переименовать или удалить исполняемые бинарные файлы службы.
4. Модифицировать или прочитать защищенные файлы конфигурации, базы данных состояния или журнал сообщений.
5. Отключить или модифицировать правила сетевой фильтрации `InternetGate`.
6. Извлечь учетные данные Telegram Bot API или хэш PIN-кода.
7. Обойти принудительное исполнение путем завершения, заморозки или сбоя процесса `tray`.
8. Выполнить привилегированные IPC-команды без знания родительского PIN-кода.

### 1.3. Границы ответственности (Out of Scope)
* Абсолютная защита от локального администратора Windows (Parent) или субъекта с правами `NT AUTHORITY\SYSTEM` (включая физический доступ с загрузочной флешки) явно **НАХОДИТСЯ ВНЕ РАМОК СИСТЕМЫ**.

## 2. Изоляция службы и архитектурные гарантии

1. **Автономность службы**:
   * Служба `service` сохраняет полную авторитетность при отсутствии активной интерактивной сессии пользователя (на экране входа в систему, при блокировке или смене пользователей).
2. **Устойчивость к завершению `tray`**:
   * Процесс `tray` выполняется с минимальными правами стандартного пользователя.
   * Принудительное завершение процесса `tray` (через Диспетчер задач или команду `taskkill`) не останавливает отсчет таймеров и не препятствует срабатыванию блокировки интернета или выключения компьютера.
3. **Стандартные механизмы надежности Windows**:
   * Служба регистрируется с автоматическим типом запуска (`SERVICE_AUTO_START`) и стандартной политикой перезапуска Windows SCM (Service Recovery Actions) при аварийном завершении.
   * Запрещено использование руткитов, скрытия процессов, перехватов таблиц ядра или недокументированных механизмов ОС; защита строится исключительно на штатных дескрипторах безопасности Windows.

## 3. Защита межпроцессного взаимодействия (IPC Security)

1. **Контроль доступа к Named Pipe**:
   * Дескриптор безопасности канала явно ограничивает доступ: `SYSTEM` (Full), `Administrators` (Full), `Child SID` (Read/Write). Сетевой и анонимный доступ безусловно запрещен.
2. **Проверка контекста вызывающего**:
   * Служба верифицирует контекст безопасности (Security Token) подключенного клиента при вызове команд.
3. **Авторизационные токены**:
   * Краткосрочные сессионные токены для привилегированных команд генерируются службой, хранятся исключительно в оперативной памяти службы, имеют короткий TTL (до 5 минут), аннулируются при перезапуске службы и привязываются к дескриптору IPC-соединения.

## 4. Защита секретов

1. **Хранение PIN-кода**:
   * PIN-код хранится в виде хэша с солью (Argon2id) в каталоге, доступном только для `SYSTEM` и `Administrators`.
2. **Защита токена Telegram**:
   * Токен шифруется с использованием Windows DPAPI для служебной учетной записи либо хранится в конфигурационном файле под строгим системным ACL.
