# Продуктовый контракт (Product Contract)

Документ устанавливает нормативные продуктовые требования к системе родительского контроля.

## 1. Функциональные требования (Functional Requirements)

1. **Запланированная блокировка Интернета (Scheduled Internet Blocking)**:
   * Система ДОЛЖНА (SHALL) поддерживать установку таймера на блокировку доступа к сети Интернет для одного сконфигурированного пользователя Windows.
   * Система ДОЛЖНА (SHALL) поддерживать немедленную ручную блокировку и немедленную ручную разблокировку (восстановление) доступа к сети Интернет.

2. **Запланированное выключение компьютера (Scheduled Computer Shutdown)**:
   * Система ДОЛЖНА (SHALL) поддерживать установку таймера на завершение работы операционной системы Windows (выключение питания).
   * Система ДОЛЖНА (SHALL) поддерживать отмену запланированного таймера выключения до наступления дедлайна.

3. **Предупредительные уведомления (Warning Notifications)**:
   * Система ДОЛЖНА (SHALL) формировать предупредительные события перед исполнением действия (блокировка Интернета или выключение компьютера) строго на следующих временных порогах до наступления дедлайна:
     * **60 минут**
     * **30 минут**
     * **20 минут**
     * **10 минут**
     * **3 минуты**
   * Если создаваемый или восстанавливаемый таймер имеет длительность меньше определенного порога, уже пройденные пороги НЕ ДОЛЖНЫ (SHALL NOT) генерироваться или отправляться.
   * Предупреждение для конкретного порога в рамках одного таймера генерируется не более одного раза.

4. **Селективность блокировки сети (Network Gate Selectivity)**:
   * Блокировка доступа к сети Интернет ДОЛЖНА (SHALL) таргетироваться исключительно на SID (Security Identifier) сконфигурированного пользователя Windows.
   * Блокировка сети НЕ ДОЛЖНА (SHALL NOT) ограничивать сетевую связность для самой привилегированной службы Windows (`service`), обеспечивая бесперебойную связь службы с Telegram Bot API.

5. **Живучесть таймеров и дифференциация просроченных дедлайнов (Timer Durability & Missed Deadlines)**:
   * Запланированные действия и их дедлайны ДОЛЖНЫ (SHALL) сохраняться и оставаться корректными при:
     * завершении или аварийном падении процесса трея (`tray`);
     * выходе пользователя из сессии (logout / sign-out);
     * перезапуске службы (`service`);
     * перезагрузке компьютера (reboot / cold restart).
   * **Просроченная блокировка Интернета**: Если дедлайн блокировки наступил во время недоступности службы, блокировка ДОЛЖНА быть применена немедленно при старте службы без ретроактивной генерации устаревших предупреждений.
   * **Просроченное выключение компьютера**: Если дедлайн выключения наступил во время выключенного состояния компьютера или недоступности службы, система НЕ ДОЛЖНА (SHALL NOT) производить немедленное выключение свежезагруженного компьютера (во избежание циклов бесконечной перезагрузки). Событие классифицируется как пропущенное выключение (`MissedDeadline`), таймер аннулируется, а родителю отправляется уведомление в Telegram.

6. **Возможности трей-приложения (Tray Application Capabilities)**:
   * Приложение в трее (`tray`) ДОЛЖНО (SHALL) обеспечивать:
     * отображение текущего состояния системы (статус сети, активные таймеры, состояние службы);
     * вывод локальных всплывающих уведомлений о предупреждениях и сообщениях;
     * интерфейс двустороннего текстового чата «родитель — ребенок»;
     * защищенный PIN-кодом ввод для выполнения административных действий на локальной машине.

7. **Авторитетность проверки PIN-кода (Authoritative PIN Verification)**:
   * Проверка корректности PIN-кода ДОЛЖНА (SHALL) производиться исключительно и авторитарно внутри компонента `service`.
   * Компонент `tray` НЕ ДОЛЖЕН (SHALL NOT) производить локальную валидацию PIN-кода и не должен хранить секреты.

8. **Удаленное управление через Telegram (Telegram Remote Control)**:
   * Telegram-адаптер службы ДОЛЖЕН (SHALL) поддерживать следующие строго определенные удаленные операции:
     * запрос текущего статуса системы (Status Query);
     * планирование блокировки Интернета (Internet Block Scheduling);
     * восстановление доступа к Интернету / отмена блокировки (Internet Restoration);
     * отмена таймера блокировки Интернета (Internet Timer Cancellation);
     * планирование выключения компьютера (Shutdown Scheduling);
     * отмена таймера выключения компьютера (Shutdown Timer Cancellation);
     * отправка сообщений от родителя ребенку (Parent-to-Child Messages).
   * Поддерживается удобный синтаксис относительной длительности (минимум `30m`, `2h`, `1h30m`), нормализуемый адаптером в доменное представление длительности.

9. **Проактивный мониторинг здоровья службы (Telegram Health Reporting)**:
   * Служба ДОЛЖНА (SHALL) проактивно информировать родителей через Telegram о ключевых событиях жизненного цикла:
     * готовность службы после старта системы (`ServiceReady`);
     * деградация состояния (`ServiceHealthChanged` -> `Degraded` / `Critical`);
     * восстановление штатной работы (`ServiceHealthChanged` -> `Healthy`);
     * пропущенные события выключения компьютера (`MissedDeadline`).
   * Служба ДОЛЖНА (SHALL) поддерживать настраиваемую периодическую отправку диагностического пульса (Heartbeat) с кратким снимком состояния (статус здоровья, режим сети, активные таймеры, время работы).

10. **Маршрутизация сообщений чата (Chat Routing)**:
    * Сообщения от ребенка родителю ДОЛЖНЫ (SHALL) передаваться из интерфейса `tray` через IPC в `service`, а затем отправляться службой в сконфигурированный Telegram-чат.
    * Сообщения от родителя ребенку ДОЛЖНЫ (SHALL) приниматься службой из Telegram и доставляться через IPC в `tray` для отображения ребенку.

11. **Ограничение доступа к Telegram и запрет произвольного исполнения (Security Scope)**:
    * Доступ к управлению через Telegram ДОЛЖЕН (SHALL) быть ограничен исключительно явно сконфигурированным списком идентификаторов пользователей и чатов.
    * Интеграция с Telegram ДОЛЖНА (SHALL) предоставлять строго замкнутый набор доменных команд.
    * Категорически ЗАПРЕЩАЕТСЯ (SHALL NOT) наличие функциональности произвольного удаленного исполнения команд (shell, PowerShell, запуск файлов или процессов).

12. **Автономность принудительного исполнения (Enforcement Independence)**:
    * Исполнение блокировки Интернета и выключения компьютера ДОЛЖНО (SHALL) непрерывно функционировать при отсутствии или принудительном завершении процесса `tray`.

## 2. Ролевая модель и защита от несанкционированного вмешательства (Anti-Tamper)

1. **Ролевая модель**:
   * Родитель (Parent Account): учетная запись с правами Администратора Windows (Windows Administrator).
   * Ребенок (Child Account): сконфигурированная стандартная учетная запись Windows (Standard User SID).
2. **Защита от стандартного пользователя (Child Anti-Tamper)**:
   * Стандартный пользователь Windows НЕ ДОЛЖЕН (SHALL NOT) иметь возможности:
     * остановить или приостановить службу через Service Control Manager (`sc.exe`, `net.exe`, `Stop-Service`);
     * изменить конфигурацию запуска или тип службы;
     * удалить службу;
     * перезаписать, переименовать или удалить исполняемые файлы службы;
     * модифицировать защищенные файлы состояния, базы данных и конфигурации;
     * отключить правила фильтрации сети `InternetGate`;
     * извлечь учетные данные Telegram Bot API или хэш PIN-кода;
     * отключить принудительное исполнение путем завершения процесса `tray`.
3. **Конфигурация службы Windows**:
   * Служба ДОЛЖНА (SHALL) устанавливаться с автоматическим типом запуска (`SERVICE_AUTO_START`) и политикой автоматического перезапуска при непредвиденном падении (Service Recovery Actions).
   * Использование руткитов, скрытия процессов или недокументированных перехватов ядра ОС ЗАПРЕЩЕНО; защита обеспечивается стандартными механизмами безопасности Windows (ACL, дескрипторы безопасности служб, права файловой системы).
4. **Границы ответственности**:
   * Абсолютная защита от пользователя с правами локального администратора Windows (Parent) явно находится вне рамок проекта (Out of Scope).
