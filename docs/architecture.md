# Архитектурный контракт (Architecture Contract)

## 1. Архитектурный инвариант (Normative Invariant)

В системе устанавливается строгий нормативный инвариант разделения ответственности:

```
CORE DECIDES
SERVICE ENFORCES
PLATFORM EXECUTES
TRAY DISPLAYS
TELEGRAM REQUESTS
```

Каждый компонент системы обязан строго следовать данному инварианту:
* **`core` (Решает)**: Чистая доменная логика, конечные автоматы, правила таймеров, валидация состояний, вычисление достижения порогов предупреждений и принятие решений о наступлении дедлайнов.
  * `core` является абсолютно чистым модулем (без побочных эффектов ввода-вывода).
  * `core` **КАТЕГОРИЧЕСКИ НЕ ДОЛЖЕН (MUST NOT)**:
    * вызывать `InternetGate`;
    * вызывать `PowerController`;
    * выполнять сетевой или межпроцессный ввод-вывод (IPC);
    * напрямую обращаться к персистентному хранилищу или файловой системе;
    * взаимодействовать с Telegram API;
    * выполнять любые системные вызовы Windows API.
* **`service` (Принуждает / Обеспечивает исполнение)**: Авторитетный компонент принудительного исполнения (authoritative enforcement). Работает как фоновая системная служба Windows (LocalSystem / privileged service). Владеет состоянием приложения, управляет персистентным хранилищем, обрабатывает доменные результаты от `core`, координирует вызовы `windows-platform`, проверяет права и авторизацию (PIN-код, списки Telegram), обслуживает IPC-сервер и интеграцию с Telegram. Сохраняет авторитетность даже при отсутствии активной интерактивной пользовательской сессии.
* **`windows-platform` (Исполняет)**: Низкоуровневая реализация системных интерфейсов Windows (абстракции `InternetGate`, `PowerController`, работа с дескрипторами безопасности и SID пользователей). Выполняет конкретные операции в ОС строго по запросу `service`.
* **`tray` (Отображает)**: Непривилегированное пользовательское приложение в трее Windows, работающее в контексте интерактивной сессии пользователя. Не является доверенным компонентом для принудительного исполнения. Отображает текущее состояние, всплывающие уведомления, интерфейс чата «родитель-ребенок» и диалоги ввода PIN для административных действий.
* **`telegram` (Запрашивает)**: Внешний канал удаленного управления (адаптер в составе `service`). Принимает только строго типизированные доменные запросы от авторизованных идентификаторов пользователей/чатов и передает исходящие события/сообщения родителям.

## 2. Компонентный состав

Система состоит ровно из четырех (4) архитектурных компонентов (контейнеров кода / крейтов):

```
+-------------------------------------------------------------+
|                           core                              |
|   (Domain Types, State Machines, Pure Logic, Timers Math)   |
+-------------------------------------------------------------+
                               ^
                               | (чистые доменные функции)
+-------------------------------------------------------------+
|                          service                            |
|  (Authoritative Daemon, Persistence, Telegram, IPC Server)  |
+-------------------------------------------------------------+
         |                                           ^
         | (вызывает абстракции)                     | (IPC: статус,
         v                                           |  команды, чат)
+-------------------------+                 +-------------------------+
|    windows-platform     |                 |          tray           |
| (InternetGate,          |                 | (UI, Notifications,     |
|  PowerController, OS)   |                 |  Untrusted Client)      |
+-------------------------+                 +-------------------------+
```

1. **`core`**:
   * Чистая бизнес-логика.
   * Полное отсутствие платформо-зависимых зависимостей (`std`-совместимый или `no_std`-совместимый Rust-модуль).
   * Детерминированное вычисление переходов состояний, порогов предупреждений и валидация команд.

2. **`service`**:
   * Долгоживущая служба Windows Service.
   * Получает события истечения дедлайнов от `core`, фиксирует состояние в хранилище и отдает команды на исполнение в `windows-platform`.
   * Сервер локального защищенного IPC для подключения `tray`.
   * Клиент Telegram Bot API для удаленного управления.
   * Проводит авторизацию: проверка PIN-кода и проверка Telegram Chat ID / User ID.
   * Изолирован от стандартного пользователя ОС.

3. **`windows-platform`**:
   * Платформенные адаптеры под Windows API.
   * Реализует контракты `InternetGate` (сетевая фильтрация на основе SID) и `PowerController` (управление питанием и выключением ОС).
   * Выполняет системные запросы к подсистеме безопасности Windows (получение SID пользователя сессии, проверка привилегий).

4. **`tray`**:
   * Интерактивное GUI-приложение в области уведомлений Windows.
   * Подключается к `service` через локальный IPC.
   * Не имеет прав на прямое управление сетевой фильтрацией или питанием.
   * Завершение процесса `tray` НЕ нарушает работу таймеров и механизмов принудительного исполнения в `service`.

Введение дополнительных runtime-компонентов категорически запрещено.

## 3. Границы доверия и модели угроз

* **Авторитетность службы (Service Authority)**: Служба `service` является единственным доверенным источником правды. Любое решение об ограничении или отключении принимается на основе `core` и обеспечивается `service`.
* **Недоверенный статус трея (Untrusted Tray)**: Трей-клиент не может самостоятельно авторизовать операцию или отменить таймер. Завершение процесса `tray` стандартным пользователем (включая принудительное завершение через Диспетчер задач) не влияет на работу службы и исполнение запланированных действий.
* **Ролевая модель**:
  * Родитель (Parent): учетная запись Windows с правами Администратора (Windows Administrator).
  * Ребенок (Child): учетная запись стандартного пользователя Windows (Standard User).
* **Границы защиты**:
  * Защита от стандартного пользователя Windows (Child) является полной: он не может изменить конфигурацию, остановить службу или обойти сетевую блокировку.
  * Абсолютная защита от локального администратора Windows (Parent) явно находится вне рамок системы (Out of Scope), так как локальный администратор Windows обладает неограниченными правами на уровне ОС.
* **Изоляция сети привилегированной службы**: Сетевой трафик службы (включая обмен с Telegram Bot API) не должен блокироваться при активации блокировки интернета для целевого пользователя. Блокировка применяется селективно по SID целевого стандартного пользователя.
