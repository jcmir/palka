# Контракт шлюза управления Интернетом (InternetGate Contract)

Документ определяет абстрактный контракт компонента `InternetGate`, отвечающего за селективное принудительное ограничение доступа к сети Интернет для сконфигурированного пользователя Windows.

## 1. Абстрактный интерфейс `InternetGate`

`InternetGate` является абстрактным интерфейсом подсистемы `windows-platform`, инкапсулирующим детали реализации сетевой фильтрации на уровне ОС Windows.

```rust
// Концептуальное представление интерфейса InternetGate
trait InternetGate: Send + Sync {
    /// Запросить применение принудительной блокировки доступа в Интернет для указанного SID
    fn block_internet(&mut self, target_sid: &SecurityIdentifier) -> Result<(), GateError>;

    /// Запросить восстановление (снятие блокировки) доступа в Интернет для указанного SID
    fn unblock_internet(&mut self, target_sid: &SecurityIdentifier) -> Result<(), GateError>;

    /// Запросить фактически подтвержденное физическое состояние шлюза
    fn current_state(&self, target_sid: &SecurityIdentifier) -> Result<InternetState, GateError>;

    /// Проверка целостности и готовности подсистемы сетевой фильтрации
    fn check_health(&self) -> Result<(), GateError>;
}
```

## 2. Нормативные требования к изоляции и селективности

1. **Таргетирование по SID (User SID Targeting)**:
   * Блокировка ДОЛЖНА (SHALL) применяться строго к процессам и сетевым пакетам, ассоциированным с `SecurityIdentifier` (SID) сконфигурированного пользователя-ребенка.
2. **Изоляция привилегированной службы (Privileged Service Exemption)**:
   * Блокировка сети НЕ ДОЛЖНА (SHALL NOT) распространяться на трафик системной службы `service` (работающей под `NT AUTHORITY\SYSTEM`) и локального администратора.
   * Связность службы со службами Telegram Bot API, DNS и локальной сетью ДОЛЖНА (SHALL) полностью сохраняться при любом состоянии `DesiredInternetState` и `InternetState`.
3. **Сохранение локального IPC**:
   * Сетевая блокировка не должна нарушать локальный обмен через Named Pipes между `tray` и `service`.

## 3. Требования к разрыву существующих соединений (Connection Teardown)

1. **Немедленный сброс активных сессий (Active Connection Termination)**:
   * Переход в состояние `DesiredInternetState::Blocked` ДОЛЖЕН (SHALL) не только запрещать открытие новых сетевых соединений (TCP SYN, UDP flows), но и принудительно обрывать (reset/abort) уже установленные и активные соединения целевого пользователя (включая активные загрузки, видеостриминг, игры и фоновые TCP-сессии).
2. **Обязательство интеграционной верификации**:
   * Реализация `InternetGate` обязана доказать в интеграционных тестах факт прекращения передачи данных по уже установленному сетевому соединению (см. [Контракт тестирования](./010-test-contract.md)).

## 4. Семантика подтверждения состояния и согласование при старте

1. **Семантика подтверждения наблюдаемого состояния**:
   * Методы `block_internet()` и `unblock_internet()` являются запросами на перевод состояния платформы.
   * Возврат `Ok(())` от метода запроса перехода **НЕ ОЗНАЧАЕТ** автоматического рапортования успеха. Служба обязана запросить подтвержденное физическое состояние через `current_state()`.
   * Наблюдаемое состояние `InternetState::Blocked` или `Unrestricted` фиксируется в системе только после успешного подтверждения от `current_state()`.
   * Если состояние не удалось подтвердить, фиксируется `InternetState::Unknown` (или сохраняется предыдущее известное), а статус службы деградирует.

2. **Двустороннее согласование политики при старте службы (Startup Reconciliation)**:
   * При инициализации служба загружает сохраненную политику `DesiredInternetState`:
     * Если `DesiredInternetState == Blocked`: служба вызывает `block_internet()` и подтверждает статус через `current_state()`.
     * Если `DesiredInternetState == Unrestricted`: служба вызывает `unblock_internet()` и подтверждает статус через `current_state()`.
   * Состояние `ServiceReady` наступает после выполнения первичной попытки согласования (даже если она завершилась ошибкой, при этом служба переходит в статус `HealthStatus::Degraded` / `Critical` и продолжает повторы).
